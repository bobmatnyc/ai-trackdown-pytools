# QA: Test GitHub sync functionality after run_in_executor() fix

## Description
The Engineer has fixed the issue where BaseEventLoop.run_in_executor() was receiving unexpected keyword arguments like 'title'. The fix involved using functools.partial() to properly bind keyword arguments before passing to run_in_executor().

TEST REQUIREMENTS:
1. Run the test suite to ensure no regressions
2. Test the sync platform GitHub push command to verify the "unexpected keyword argument" error is resolved  
3. Confirm that items with attributes (title, body, labels) are now properly passed to the GitHub API
4. Verify both GitHub and Jira adapters work correctly (both were fixed)

FILES MODIFIED:
- src/ai_trackdown_pytools/utils/sync/github_adapter.py  
- src/ai_trackdown_pytools/utils/sync/jira_adapter.py

FOCUS AREAS:
- Both _run_async() methods now use functools.partial() when keyword arguments are present
- Verify sync commands work without executor argument errors
- Test both GitHub and Jira sync functionality 
- Ensure no regressions in existing functionality

Expected outcome: GitHub sync should work properly without "unexpected keyword argument" errors, and all sync functionality should be operational.
