# ENGINEER: Fix GitHub CLI --json flag error in sync adapter

## Description
**TARGET: Engineer Agent**
**PRIORITY: HIGH - Critical Bug Fix**

**PROBLEM SUMMARY**:
The GitHub sync adapter in `src/ai_trackdown_pytools/utils/github_utils.py` contains invalid GitHub CLI commands that use `--json` flag with create operations, which is not supported.

**AFFECTED METHODS**:
1. `create_issue()` method (around lines 102-103)
2. `create_pr()` method (around lines 267-268)

**CURRENT BROKEN CODE PATTERN**:
```bash
gh issue create --json number,title,url  # INVALID - create doesn't support --json
gh pr create --json number,title,url     # INVALID - create doesn't support --json
```

**REQUIRED FIX IMPLEMENTATION**:

**Step 1**: Add URL parsing utility function
```python
def extract_number_from_github_url(url_text):
    """Extract issue/PR number from GitHub URL"""
    # Parse URL format: https://github.com/owner/repo/issues/123
    # Return the number (123)
```

**Step 2**: Fix create_issue() method
```python
# Replace invalid single command with two-step process:
# 1. Create issue without --json
result = subprocess.run(['gh', 'issue', 'create', '--title', title, '--body', body], 
                       capture_output=True, text=True)
# 2. Parse number from output URL
issue_number = extract_number_from_github_url(result.stdout.strip())
# 3. Get JSON details with view command
json_result = subprocess.run(['gh', 'issue', 'view', str(issue_number), '--json', 'number,title,url'])
```

**Step 3**: Fix create_pr() method using same pattern

**TECHNICAL REQUIREMENTS**:
- Maintain existing method signatures and return formats
- Preserve all error handling logic
- Ensure subprocess calls use `text=True` for proper encoding
- Test both methods work end-to-end

**VALIDATION**:
- Both methods should create GitHub items successfully
- Both methods should return proper JSON response format
- No more CLI --json flag errors

**FILES TO MODIFY**: `src/ai_trackdown_pytools/utils/github_utils.py`
